# Passo 4: Configuração do Arquivo ``database.py``

O arquivo ``database.py`` tem como objetivo:

**1. Gerenciar a conexão com o banco de dados PostgreSQL:**

- Vamos usar a biblioteca **SQLAlchemy** para criar e gerenciar conexões de forma eficiente.

**2. Centralizar a configuração do banco de dados:**

- Todos os componentes da aplicação usarão este arquivo para interagir com o banco de dados.

**3. Garantir boas práticas:**

- Incluiremos o uso de sessões e conexão assíncrona para integração perfeita com o FastAPI.

---

## Explicação do Código ``database.py``

---
**1. Importações:**

``from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine:``

- Aqui importamos o ``AsyncSession`` e o ``create_async_engine`` da ``SQLAlchemy``, que nos permitem criar conexões assíncronas com o banco de dados. Isso é importante para manter a aplicação rápida e responsiva, especialmente em cenários com muitas requisições simultâneas.

``from sqlalchemy.orm import sessionmaker:``

- O ``sessionmaker`` é usado para criar uma fábrica de sessões, que nos ajuda a gerenciar as transações com o banco de dados.

``from app.config import DATABASE_URL:``

- Importamos a URL do banco de dados definida no ``config.py``. Isso garante que as credenciais e configurações estejam centralizadas.

~~~python
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine
from sqlalchemy.orm import sessionmaker
from app.config import DATABASE_URL
~~~

---
**2. Criando o Motor do Banco de Dados:**

``engine = create_async_engine(DATABASE_URL, future=True, echo=True):``

- Aqui criamos o motor assíncrono que se conecta ao banco de dados PostgreSQL usando a URL fornecida.

**Parâmetros usados:**

- ``DATABASE_URL:``
  - A URL do banco de dados, como ``postgresql+asyncpg://user:password@host/dbname``.

- ``future=True:``
  - Garante compatibilidade com versões futuras da SQLAlchemy.

- ``echo=True:``
  - Ativa o modo de depuração, exibindo todas as consultas SQL executadas no terminal. Isso é útil durante o desenvolvimento, mas pode ser desativado em produção.

~~~python
engine = create_async_engine(DATABASE_URL, future=True, echo=True)
~~~

---
**3.  Criando a Fábrica de Sessões:**

``sessionmaker:``

- É uma fábrica que cria instâncias de sessão para interagir com o banco de dados.

**Parâmetros usados:**

- ``bind=engine:``
  - Liga a fábrica de sessões ao motor do banco de dados.

- ``class_=AsyncSession:``
  - Especifica que as sessões serão assíncronas.

- ``expire_on_commit=False:``
  - Evita que os objetos carregados da sessão sejam expirados automaticamente após um commit.

~~~python
async_session_factory = sessionmaker(
    bind=engine,
    class_=AsyncSession,
    expire_on_commit=False
)
~~~

---
**4. Dependência do Banco de Dados:**

``async def get_db():``

- Essa função é uma dependência que pode ser usada em endpoints do FastAPI para acessar o banco de dados.

``async with async_session_factory() as session:``

- Garante que a sessão seja criada e fechada corretamente após o uso. Isso evita vazamentos de conexão.

``yield session:``

- Entrega a sessão para o endpoint que a está chamando. Depois que o endpoint termina de usá-la, o ``async with`` automaticamente fecha a sessão.

~~~python
async def get_db():
    async with async_session_factory() as session:
        yield session
~~~

---

## Como esse arquivo se conecta ao resto da aplicação?

Qualquer componente da aplicação que precisar interagir com o banco de dados pode usar a dependência ``get_db``.

- Por exemplo, um endpoint no FastAPI pode obter uma sessão de banco de dados injetando ``Depends(get_db)``.
