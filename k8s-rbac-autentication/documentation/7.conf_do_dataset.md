# Passo 6: Configuração do Arquivo ``schemas/dataset.py``

O objetivo do arquivo ``schemas/dataset.py`` é:

**1. Definir como os dados enviados pelo cliente devem ser validados:**

- or exemplo, garantir que o nome de usuário seja uma string e que a senha atenda a critérios específicos.

**2. Controlar o formato da resposta enviada ao cliente:**

- Por exemplo, ocultar informações sensíveis como senhas.

**3. Garantir validação automática de dados:**

- Usar o Pydantic para validar automaticamente os dados recebidos ou enviados pela API.

**4. Manter a separação de responsabilidades:**

- Diferenciar os esquemas usados para criação de usuários, atualização de dados e resposta da API.

---

## Explicação do Código ``schema/dataset.py``

---
**1. Importações:**

``from pydantic import BaseModel, Field:``

- Importamos a classe ``BaseModel`` do ``Pydantic``, que serve como base para criar nossos esquemas.
- Ela oferece validação automática de dados e integração perfeita com o FastAPI.
- ``Field:``
  - Usado para personalizar as validações, limites e descrições dos campos.

~~~python
from pydantic import BaseModel, Field
~~~

---
**2. Esquema Base:**

``class UserBase(BaseModel):``

- Define os atributos comuns a todos os esquemas relacionados ao usuário.
- Neste caso, todos os usuários possuem um ``username``.

``...:``

- Indica que o campo é obrigatório.

``min_length=3:``

- O nome de usuário deve ter pelo menos 3 caracteres.

``max_length=50:``

- O nome de usuário pode ter no máximo 50 caracteres.

``description:``

- Uma descrição usada na documentação gerada pelo FastAPI.

~~~python
class UserBase(BaseModel):
    """
    Esquema base para representar dados de usuários.
    """
    username: str = Field(..., min_length=3, max_length=40, description="Nome do usuário único")
~~~

---
**3. Esquema para Criação de Usuário:**

``class UserCreate(UserBase):``

- Herda os atributos de ``UserBase`` e adiciona o campo de senha.
- Esta classe é usada para validar os dados enviados ao registrar um novo usuário.

``min_length=6``

- Define que a senha deve ter no mínimo 6 caracteres.

``description:``

- A descrição será exibida na documentação da API.

**Por que password não está em UserBase?**

- Para evitar que o atributo seja exposto em respostas da API.

~~~python
class UserCreate(UserBase):
    """
    Esquema para criar um novo usuário.
    """
    password: str = Field(..., min_length=6, description="Senha do usuário (mínimo 6 caracteres).")
~~~

---
**4. Esquema de Resposta:**

``class UserResponse(UserBase):``

- Herda os atributos de ``UserBase`` e adiciona o campo id.
- Esta classe é usada para definir o formato da resposta do servidor ao cliente.

``class Config:``

- Permite que o Pydantic converta automaticamente objetos ORM (como os modelos SQLAlchemy) em dicionários JSON. Graças à opção ``orm_mode = True``.

~~~python
class UserResponse(UserBase):
    """
    Esquema para responder dados de um usuário.
    """
    id: int = Field(..., description="Identificador único do usuário.")
    class config:
        orm_mode = True
~~~

---

## 3. Por que separar esquemas para criação e resposta?

**Segurança:** O esquema de resposta não inclui a senha do usuário, protegendo dados sensíveis.
Apenas informações necessárias são enviadas ao cliente.

**Flexibilidade:** Esquemas distintos permitem maior controle sobre como os dados são validados e manipulados.

|Nome do Esquema|Uso|Campos|
|-|-|-|
